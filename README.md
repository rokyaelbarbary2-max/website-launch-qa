# Website launch QA

A practical checklist for the last week before a marketing website (or a redesign) goes live, and the first week after.

It is written for small teams where one marketer, one developer and maybe one designer share responsibility for launch, and nobody owns "QA" full-time. Every item is something that commonly breaks quietly on launch day: forms that stop delivering leads, tracking that double-counts, redirects that were never deployed, staging rules that block search engines, or a right-to-left layout that only one person ever checked.

## How to use it

- **As a document:** open [`CHECKLIST.md`](CHECKLIST.md), copy it into your project tracker and assign an owner to each section.
- **As a GitHub issue:** copy [`.github/ISSUE_TEMPLATE/launch-qa.md`](.github/ISSUE_TEMPLATE/launch-qa.md) into your own repository. GitHub will offer it as a template when someone opens a new issue, with every item as a tickable box.

Not every item applies to every site. Delete what you do not need rather than ticking it blindly, and add the checks your own stack needs.
